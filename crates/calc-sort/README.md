# calc-sort

## What it does

Sorts any entries with a comparison that may fail, by a named method written in this project, and counts on the way every comparison and every write, exactly. `sort` returns the arrangement that sorts the entries, as the input position of each entry of the result, together with the counts and, when asked, every step. It never reorders the caller's entries. The first comparison that fails stops the sort, and the failure comes back with the two entries and the counts reached. `costs` gives each method's best, worst and average comparisons and writes as formulas in the length, which evaluate exactly, with where each comes from. `comparison_lower_bound` gives ⌈log₂ n!⌉. Counting sort compares nothing, so `sort` refuses it and `sort_whole_numbers` runs it on whole-number keys whose range is at most `COUNTING_RANGE_LIMIT`, counting each counter update besides the writes. Quicksort with `Partition::LomutoRandom { seed }` draws each pivot from `calc-kernels`' Philox4x32-10 and counts the blocks it reads; `quick_sort_with_chosen_pivots` takes the pivot choices from its caller instead, which is how the expected costs over uniform choices are checked. Double selection, cocktail shaker, gnome, odd–even, comb, cycle and pancake sort follow their published sources; pancake sort counts flips as a third measure, and a cost row is derived, fitted to the counts and checked, or not stated. Shell sort runs with the gap sequence `Gaps::Shell`, `Knuth` or `Ciura`, and `gaps_for` names the gaps it uses at a length. Bottom-up and natural merge sort use merge sort's merge step, the first on runs of 1, 2, 4, … entries, the second on the runs already in order. `radix_sort_whole_numbers` sorts whole-number keys digit by digit in a base from 2 to `RADIX_BASE_LIMIT`, one stable counting pass per digit of the largest key less the least, and says how many passes it made; its writes are 2n per pass and are stated per pass, since the passes depend on the keys. `bead_sort_whole_numbers` lays whole numbers of at least 0 out as beads on poles, lets them fall and reads each row back, so it returns the rebuilt values rather than an arrangement; it counts two counter updates per bead and one write per row, and refuses a number below 0 and more than `BEAD_LIMIT` beads. `Method::Bitonic` is Batcher's bitonic network for 0 or 2^k entries; `sort` refuses any other length with `Refusal::LengthNotAPowerOfTwo`, and its rows hold over `Over::OrdersAtPowersOfTwo`. `Method::Bogo { seed, limit }` tests the order from the left and shuffles by Fisher–Yates with draws from `philox4x32_10` on stream 1 until the list is sorted; at `limit` shuffles `sort` gives `Refusal::LimitReached` with the counts, and `Counts::shuffles` counts the shuffles; its rows state the fewest counts, no most, and the average writes per shuffle, checked up to `BOGO_CHECK_LIMIT`.

The crate has no user-facing text and depends on `calc-numbers` only. `calc-core` uses it to order exact values, and `calc-app` maps its reports to messages.

## How to test

`cargo test -p calc-sort`

`tests/exhaustive.rs` runs each method on every order of n distinct entries for every n up to `EXHAUSTIVE_CHECK_LIMIT` and compares the fewest, the most and the exact average of its comparisons and writes with every formula `costs` states; a formula wrong by one is shown to be caught. `tests/insertion.rs` holds a worked example, `[3, 1, 2]`, step by step.

`tests/pivots.rs` does the same for quicksort with a random pivot up to `PIVOT_CHOICE_CHECK_LIMIT` entries, over every order and every sequence of pivot choices, each weighted by its probability; the expected comparisons are checked for each order separately.
